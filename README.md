# 🦏 Rhino Algorithm Study

기업 코딩테스트와 삼성 SW 역량평가 A형을 함께 준비하는 알고리즘 스터디입니다.

매주 정해진 문제를 풀고 GitHub에 코드를 기록하며, 정기 스터디 시간에는 풀이 아이디어와 개선점을 함께 리뷰합니다.

우리는 코딩테스트에 미쳐있고 너무 즐겁고 한 문제 한 문제가 기대 됩니다.

---

## 🎯 스터디 목표

1. 삼성 SW 역량평가 A형 대비
2. 기업 코딩테스트 핵심 유형 학습
3. 꾸준한 문제 풀이 습관 형성
4. 서로 다른 풀이 방식 비교
5. 설명할 수 있는 수준까지 문제 이해하기
6. 코딩테스트는 재밌다고 세뇌하기

---

## 📅 진행 방식

- 매주 공통 문제 **5문제**를 풉니다.
- 문제 목록, 일정, 출석, 회고는 **Notion**에서 관리합니다.
- 풀이 코드는 해당 주차 폴더 안의 개인 폴더에 업로드합니다.
- 푼 코드는 notion에 자신의 풀이란에 올려두고 회고합니다.
- 매주 스터디 시간에 notion 에 올려둔 서로의 코드를 보며 리뷰합니다.
- 매주 자신이 뽑은 문제의 풀이를 발표합니다. (질문 들어왔을 때 대답할 수 있어야 함)
- 해결하지 못한 문제는 풀이를 이해한 뒤 다시 풀어봅시다.

## 📁 파일 및 폴더 구조

저장소는 다음 순서로 관리합니다.

```text
주차 → GitHub 아이디 → 문제 → 풀이 파일
```

전체 구조 예시:

```text
rhino-algorithm-study
├─ README.md
├─ .gitignore
│
├─ week01
│  ├─ yeajeong
│  │  ├─ BOJ_2178.java
│  │  ├─ PG_42576.java
│  │  └─ SWEA_1954.java
│  │
│  ├─ minsu
│  │  ├─ BOJ_2178.cpp
│  │  ├─ PG_42576.cpp
│  │  └─ SWEA_1954.cpp
│  │
│  └─ member3
│     └─ ...
│
├─ week02
│  ├─ yeajeong
│  ├─ minsu
│  └─ member3
│
└─ week03
```

권장 경로 형식:

편의상 아래와 같이 규칙을 정하지만 폴더 구조만 파일명은 원하는 대로 하셔도 상관 없습니다.

```text
week{주차}/{이름 or GitHub아이디}/{플랫폼}_{문제번호}.{확장자}
```

예시:

```text

week01/yeajeong/PG_42576.java
week01/minsu/PG_42576.cpp

week01/yeajeong/SWEA_1954.java
week01/minsu/SWEA_1954.cpp
```

---

### Convention. 문제 폴더 이름은 플랫폼과 문제 번호로 작성합니다

```text
BOJ_2178
PG_42576
SWEA_1954
```

문제 제목은 파일명이나 폴더명에 반드시 넣지 않아도 됩니다.

한글 파일명으로 인한 인코딩 문제를 줄이기 위해 기본적으로 문제 번호 중심으로 작성합니다.

## ✅ 코드 업로드 방법

### 처음 한 번만

```bash
git clone https://github.com/Coding-Rhinoceros/rhino-algorithm-study.git
cd rhino-algorithm-study
```

### 문제를 올리기 전

항상 최신 내용을 먼저 받아옵니다.

```bash
git pull origin main
```

### 자기 폴더 추가

예시:

```text
week01/yeajeong/SWEA_2178.java
```

### Git에 추가

가능하면 저장소 전체가 아니라 자신의 폴더만 추가합니다.

예시:

```bash
git add week01/yeajeong
```

### 커밋

```bash
git commit -m "solve: week01 문제 풀이"
```

### 업로드

```bash
git push origin main
```

## 🔍 코드 리뷰 방식

문제별 풀이 발표는 매주 스터디 시간에 진행합니다.

다음 내용을 포함해서 발표해주세요

- 어떤 알고리즘을 사용했는가
- 문제를 어떤 순서로 해결했는가
- 시간복잡도가 입력 범위에 적합한가
- 불필요한 반복이나 중복 계산은 없는가
- 방문 처리와 히든 케이스가 있는가
- 다른 풀이 방법은 무엇인가
- 다시 푼다면 어떤 부분을 개선할 것인가

발표자는 다음 내용을 설명합니다.

1. 문제 핵심 조건
2. 사용한 알고리즘
3. 풀이 순서
4. 시간복잡도
5. 어려웠던 부분
6. 다른 사람과 풀이가 달랐던 부분

## 🚫 업로드하지 않는 파일

다음 파일은 저장소에 올리지 않습니다.

```text
.class
.exe
.out
.o
bin/
build/
out/
.settings/
.idea/
.vscode/
```

IDE 설정 파일, 컴파일 결과물, 실행 파일은 각자의 로컬 환경에서만 사용합니다.

## 📌 주의사항

- 문제 원문 전체를 README에 복사하지 않습니다.
- 문제 링크, 번호, 제목만 기록합니다.
- 다른 사람의 풀이를 그대로 복사하지 않습니다.
- 실패한 풀이도 학습 목적상 남길 수 있지만, 파일명이나 주석으로 구분합니다.

실패 풀이 예시:

```text
Main_failed.java
Solution_retry.java
```
